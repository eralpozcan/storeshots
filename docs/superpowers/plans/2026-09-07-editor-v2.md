# Editor V2 implementation plan

**Goal:** Ship an opt-in, three-stage editor while keeping `/editor` stable.
**Architecture:** An independent `/editor-v2` page uses the existing `useScreenshots`, SlideCard, SlideTemplate, AppSidebar and export capture routine. Inject V2 persistence into the existing composable; keep its default behavior unchanged. Store the V2 draft in IndexedDB and its API key in sessionStorage.
**Tech stack:** Existing Nuxt/Vue, native IndexedDB, html-to-image, JSZip. No added dependencies.
**Spec:** `docs/v2-design-proposal.md` (approved).

## Work
- [ ] Add a runnable Node assertion check for upload capacity and export selection. Run it before implementing helpers.
- [ ] Add isolated V2 persistence; route both composable save calls through an optional persistence argument. Existing callers retain default load/save functions.
- [ ] Share the existing PNG capture function without changing its behavior. Build V2 upload, design and download screens with large selected-slide preview, editable copy, template previews, colors, thumbnails and advanced settings.
- [ ] Add explicit V2 links and a return link. Copy V1 through its exported project file, rather than silently reading or changing its draft.
- [ ] Run the assertion check, production build and browser checks for both routes, mobile layout, uploads, reload, editing, isolated saves and download.

## Specific checks
`node tests/editor-v2.test.cjs`: fill empty screenshot slots without overwriting existing slots; reject overflow; skip empty exports while preserving trust slides.
Browser: upload PNG/JPEG, replace/remove an image, choose a template, edit headline and colors, move back and forth, reload, download PNG/ZIP, visit V1 and confirm its saved values are unchanged. Check errors, keyboard focus and 390px layout.
